# Single deployment / release gate

1. CI and package run must both be green on the same commit. Keep prior compatible binary. Download lceweb-package (outer ZIP); take SHA256 of inner lceweb.zip from package log.
2. Obtain editorial approval and revalidate MVE against latest DOF, provider/compliance scope, and translations. New pages are noindex and excluded from sitemap in source until approval. Check domain in Azure and HTTPS; do not change DNS or move production WordPress without explicit plan. Choose current Azure origin if corporate domain is not ready. Verify domain ownership, CNAME/TXT, App Service binding and certificate; redirect old paths only after inventory/approval. Entra redirect URI must match the exact final origin.
3. Run scripts/azure/i22-i25-release.ps1 -ArtifactPath <outer.zip> -ExpectedPackageSha256 <hash> in Cloud Shell first without -Apply (read-only). It validates package, target, permissions on historical v1, host and config. Do not share secret settings. If checks pass and client approves editorial, rerun with -Apply -ApproveEditorial -ApprovedOrigin <https origin>. One code deploy; seed v2 after checking compatible binary, never overwrite v1. Script checks public HTTP and private scoring projection; no live lead automatically created.
4. Live acceptance: mobile/desktop in all four languages; consent reject/accept; create one explicitly authorized test lead, check table row and advisor email; verify no PII in analytics. Keep admin/upload disabled until Entra authorized/denied accounts tested, attachment quarantine and trusted scan result integration plus updated privacy notice approved. Separate configuration activation may restart the app; no second code deploy for admin if validated code and configuration are adequate. Clean-file download code is present; a trusted scan-release workflow and scoped RBAC still require provisioning and acceptance before attachment activation.
5. Failure: do not blindly restore I15 after v2 seed (it might expose weights). Stop public capture if appropriate using approved settings and restore only a v2-aware build. Preserve all leads and both version rows; reconcile failed operations and retain previous artifact and release SHA. DNS rollback is a separate authorized operation. Do not claim deployment success without live verification.
