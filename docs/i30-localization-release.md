# I30 — International public site

The twelve canonical routes (home, three services, six landings, assessment and privacy) have static ES/EN/FR/PT HTML, the same visual markup and original route IDs. Rebuild with `npm run build:i18n`; dictionaries are in scripts/i18n. The generator fails on untranslated visible text and human-facing attributes. Legacy /diagnostico.html?lang=xx links remain valid; localized routes are /en/, /fr/, /pt/ and matching pages. The global selector preserves campaign/contact query values and fragment. Language persists via localized links, not tracking cookies. Embedded logistics assessment, landing contact variants, consent UI and lead language are localized. Existing diagnostic definitions and stored records are untouched.

Spanish editorial release already approved at I25 is preserved. Reference translations of the Spanish privacy notice are explicitly non-authoritative, noindex, and link to the original. The approved notice itself still describes optional telephone and browser scoring; a separate legal revision is necessary for v2 mandatory callback phone/server scoring and later technical attachments. Do not enable attachments before approval.

All new translated marketing pages are noindex until LCE reviews specialist terminology. The I30 release script can index the 33 non-privacy translations with -ApproveTranslations after approval (45 total sitemap URLs); otherwise they remain usable but not indexed (12 Spanish URLs). No guarantees of search ranking.

Deployment: download the new GitHub Actions artifact, use the SHA256 of the inner lceweb.zip from that same run, and fetch scripts/azure/i30-release.ps1 at the exact package commit. Run with -ArtifactPath and -ExpectedPackageSha256, first without -Apply. Then repeat with -Apply only after preflight. It performs one ZIP deployment, validates 48 language routes and v1/v2, preserves existing public capability settings, does not seed/rewrite Azure Tables and does not change DNS, Entra, ACS, or settings. No real lead is created. A live browser test remains required. Confirm the test lead row and actual inbox separately; absent Email__Provider defaults to None. No assumption about why the earlier QA query was empty.
