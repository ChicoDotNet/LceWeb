# I18 / secure attachment release

Quarantine and clean container must be distinct and private. App managed identity: upload access scoped to quarantine; read-only on clean. A separate trusted process/identity may write clean blobs after checking a verified Defender scan event or Log Analytics verdict for the exact original blob and ETag, verifying integrity and copying under the exact original generated blob key. No public SAS, no client-side choice of release key, no mutable index tag as the sole basis for release. Configure Defender on-upload scanning and trusted destination, enforce clean-writer RBAC, retention/deletion policy, and verify missing/failed/malicious verdicts remain quarantined.

App settings: Attachments__ServiceUri / ContainerName, Attachments__CleanServiceUri / CleanContainerName, Attachments__CleanReadEnabled (default false), Attachments__MalwareScanningConfigured, Attachments__PrivacyNoticeVersion, Attachments__PublicUploadEnabled (default false). Public intake also requires enabled Entra admin and authorized lead capture. The private download path checks length, SHA256 and ETag of the clean copy and serves an attachment with nosniff; absent copy or mismatch is denied. No automatic scan release is implemented by this web app. Provision and test a trusted release workflow separately, including clean test file, malicious simulation using an approved test artifact, failed verdict, hash mismatch, unauthenticated user, role denial, and blocked upload when gates disabled. Do not enable upload simply because code compiles.
