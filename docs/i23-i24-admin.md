# I23–I24 · Entra and internal lead operations

Admin is disabled unless explicitly enabled and configured. Configuration keys: Admin__Enabled, Admin__TenantId, Admin__ClientId, Admin__ClientSecret (Key Vault reference or protected App Setting, never git), Admin__PublicOrigin (approved HTTPS origin). Register a single-tenant confidential web application with exact redirect URI {origin}/signin-oidc, require user assignment, assign app roles Lce.Advisor or Lce.Admin to approved users. Confirm MFA/conditional access in the tenant. Validate actual allowed and denied accounts. App signs and validates OIDC via framework, with PKCE, one-hour non-sliding cookie and CSRF protection for writes; no access tokens stored. Logout is local only. Configure reliable Data Protection keys before scaling instances. Restrict access to app settings/storage.

Back office lists 50 records/page with continuation, score filter, detail with versioned answer labels, email status, interests, language, consent, follow-up stages and optimistic-concurrency writes (last actor and time). Records within each page are sorted by date; no global date ordering yet. V1 has no commercial score. No public lead retrieval or exports. Attachments display metadata only; downloads remain disabled until trusted scan results (Event Grid/Log Analytics and secure read design) and revised privacy approval are verified. Defender blob tags alone are not tamper-resistant. Do not enable Admin or public upload on production without real tenant tests and approved access/retention decisions.
